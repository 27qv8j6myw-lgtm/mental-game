# 멘탈게임 ⛳

골프 내기 정산 앱. 스코어만 입력하면 배판·버디·핸디캡까지 자동으로 계산하고,
최소 횟수의 송금으로 정산해 줍니다. 미드센추리 모던 스타일의 모바일 UI.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입체크 + 프로덕션 빌드
```

## 주요 기능

- **세팅**: 골프장/날짜/티오프(기본값: 현재 시각), 타당 금액(1천·2천·5천·직접입력)
- **게임 방식**: 타당(두 명씩 타수 차) / 스킨스 중 선택
  - 스킨스: 홀마다 스킨 1개(= 타당 금액). 그 홀 **단독 최저 타수**가 쌓인 스킨을 모두 가져가
    다른 참여자 모두에게서 `스킨 수 × 타당 금액`씩 받음
  - 최저 타수가 2명 이상이면 다음 홀로 이월(스킨 +1). 마지막 홀이 최저 동타면 동타인 사람끼리
    나눠 가짐(전원 동타면 소멸)
  - **배수 조건**: 배수 총 상한(×2/×4/×8/무제한) + 토글 3가지 (새 라운드 기본: 모두 켜짐, 상한 ×4)
    - 이월하면 2배: 이월 스킨이 1→2→4→8개로 불어남 (끄면 1개씩)
    - 버디·이글 배수: 버디로 이기면 ×2, 이글 이상 ×3
    - 후반 가중: 마지막 3개 홀(18홀이면 16~18번, 9홀이면 7~9번) ×2
  - 타당의 배판·버디 추가 정산 없음, 핸디캡은 타당과 같이 별도 정산(또는 타수 보정), 홀 최대 타수는 더블파까지
  - 진행 화면: 판돈이 커질수록 뜨거워지는 판돈 카드, 스킨 획득 연출, 홀별 스킨 흐름(승자 이니셜·이월·나눔)
- **지불 방법**: 현금 지급(핸디 사전 정산만) / 계좌이체(사후 정산 기본, 사전으로 변경 가능)
  계좌이체 라운드는 대기실에서 각자 은행·계좌번호 입력(내 계정에 저장해 다음 라운드 자동 입력),
  최종 송금 줄마다 받는 사람 계좌·금액 복사 버튼
- **핸디캡 설정 방식**: 평균타수 입력(핸디 = 평균−72, ± 조정) 또는 최저핸디 대비 +5·+10타·직접 입력.
  최저핸디 대비 방식은 방장이 대기실에서 최저핸디 인원을 정해야 게임을 시작할 수 있음
  - 타수 보정: 핸디캡 금액 정산 대신, 방장이 사람마다 파4·파5 홀당 잡아줄 타수(0·1·2)를 정함.
    보기 이상일 때만 그만큼 빼고 파 아래로는 내려가지 않음(2타 보정이면 더블보기 → 파).
    타당·스킨스 모두 승패·타수 차를 보정 타수로 판정하고, 배판 조건·버디는 실제 타수로 봄
- **배수 총 상한**: ×2 / ×4 / ×8 / 무제한 (배판 조건과 이월을 곱한 배수에 모두 적용)
- **배판 규칙** (고정 룰)
  1. 배판 조건은 홀당 1회 (트리플 2명이어도 ×2 한 번)
  2. 조건이 겹치면 곱해서 반영 (트리플 3명 동타 = 트리플 ×2 × 3명 동타 ×2 = ×4, 총 상한 적용)
  3. 전원 동타는 조건 없이 정산 없음 → 다음 홀 ×2 이월 (전 홀도 이월이었으면 ×4)
  4. 전원 동타가 이어지면 이월이 총 상한까지 누적
  5. 돈이 움직인 홀의 다음 홀은 ×1 로 이월 종료
  6. 3명 동타 조건은 전원 동타가 아닐 때만 (3인 플레이에서는 미적용)
  7. 마지막 홀 뒤에 남은 이월은 소멸
  8. 버디 추가 정산은 버디 1타·이글 2타, 버디 배판에서는 이글도 버디와 같이 ×2
  9. 홀 최대 타수는 더블파까지 반영
  10. 판정은 핸디 없이 실제 타수 (핸디는 별도 정산)
  - 조건: 파 페널티(파3 더블보기+ / 파4·5 트리플보기+) 또는 더블파(택1), 3명 동타, 버디 배판
- **버디 추가 정산**: 버디 1타·이글 2타를 더 잡아줌(그 홀 배수 적용), 별도 표시
- **게임 화면**: 홀 이동, PAR 선택, 스코어(-2~+5) 입력, 실시간 자동 정산.
  다시 열면 마지막으로 스코어를 입력한 홀의 다음 홀로 이동
- **정산 결과**: 순위(타수·핸디) → ① 게임 순수 → ② 버디(홀별 상세) → ③ 핸디캡 → ④ 최종 송금
  → ⑤ 홀별 검증(1번~마지막 홀을 넘기며 홀별·누적 금액 확인).
  스킨스 라운드는 ① 스킨스(인별 합계·홀별 획득/이월/소멸) → ② 핸디캡 → ③ 최종 송금 → ④ 홀별 검증.
  방장은 정산 확정 후에도 스코어와 정산 설정(게임 방식·지불 방법·핸디캡·배판 규칙)을 수정 가능
  (수정 완료 전까지는 저장되지 않고 취소 가능). 확정 후 수정 내역은 결과 화면 맨 아래에 모두에게 공개
- **멀티플레이어 라운드**: 로그인 후 한 명이 라운드를 만들면 **4자리 초대 코드**가 발급되고,
  다른 참여자는 코드로 참여. 각자 대기실에서 본인 정보(이름·평균타수·핸디)를 입력하고
  방장이 게임을 시작. 스코어 입력은 **실시간 동기화**(Supabase Realtime)
- **내 라운드**: 참여한 라운드 목록(대기중/진행중/완료, 타당/스킨스, 참여자 이름) 확인 및 다시 열기. 삭제는 방장만 가능
- **관리자 대시보드**: 관리자로 등록된 계정만 프로필 메뉴에서 열 수 있음 (`supabase/admin.sql`)
  - 가입자: 전체·오늘·최근 7일·7일 내 로그인, 일별 신규 가입(30일), 로그인 방식(구글/카카오/둘 다)
  - 라운드: 전체·오늘·최근 7일, 일별(30일)·주별(12주) 생성, 진행 상태·게임 방식·핸디캡 방식·지불 방법 비율,
    평균 인원, 많이 쓰는 타당 금액, 정산 확정 후 수정된 라운드·수정 횟수
  - 최근 라운드 30개, 최근 가입자 30명(이메일은 앞 2글자만, 계좌번호는 보여주지 않음)

## 백엔드(Supabase) 연결

구글 로그인과 기록 저장은 **Supabase**(Auth + Postgres)를 사용합니다.

1. [Supabase](https://supabase.com)에서 프로젝트 생성
2. **Authentication → Sign In / Providers → Google** 사용 설정
   - Google Cloud Console에서 OAuth 클라이언트를 만들고 Client ID/Secret 입력
   - **Authentication → URL Configuration** 에서 Site URL과 Redirect URLs 에
     로컬(`http://localhost:5173`, `5174`)과 배포 도메인(`https://<앱>.vercel.app`)을 등록
   - **카카오 로그인**: [Kakao Developers](https://developers.kakao.com)에서 앱 생성 후
     - **앱 설정 → 앱 → 플랫폼 키 → REST API 키** 에서 카카오 로그인 Redirect URI 에
       `https://<프로젝트>.supabase.co/auth/v1/callback` 등록, Client Secret 활성화 후 복사
     - **제품 설정 → 카카오 로그인** 사용 설정 ON, **동의항목**에서 닉네임·프로필 사진 설정
       (앱이 이메일을 요청하지 않으므로 비즈 앱 전환·이메일 동의항목은 필요 없음)
     - REST API 키(Client ID)와 Client Secret 을 Supabase **Providers → Kakao** 에 입력
     - Supabase Kakao 설정의 **Allow users without an email** 을 반드시 켜기
   - **구글·카카오 계정 연결**: **Authentication → Sign In / Providers** 에서
     **Allow manual linking** 을 켜기 (홈 화면 프로필 메뉴의 "로그인 계정 연결"에 필요)
3. **SQL Editor** 에서 `supabase/schema.sql` 을 실행
   (rounds / round_players / round_holes / round_scores 테이블 + RLS + RPC + Realtime publication)
   - 마지막 `alter publication ... add table` 구문은 이미 추가돼 있으면 에러가 날 수 있으니
     그 경우 무시하거나 개별 실행하세요.
4. (선택) 관리자 대시보드: `supabase/admin.sql` 을 실행한 뒤, 파일 맨 위 안내대로
   내 계정 id 를 `public.admins` 에 등록
5. **Project Settings → API** 의 값을 `.env` 에 입력 (`.env.example` 참고)

```bash
cp .env.example .env
# VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY 채우고 다시 실행
npm run dev
```

RLS 정책으로 **라운드 멤버(방장 또는 참여자)만** 해당 라운드 데이터를 읽고 쓸 수 있어,
초대 코드를 받은 사람만 라운드에 접근할 수 있습니다.

> 앱은 카카오·구글 로그인 후에만 사용할 수 있어, `.env` 설정이 필요합니다.

## Vercel 배포

이 프로젝트는 Vite SPA 로 Vercel에 그대로 배포됩니다 (`vercel.json` 포함).

1. GitHub 저장소에 푸시 후 [Vercel](https://vercel.com)에서 Import
2. Framework Preset: **Vite** (자동 감지) · Build: `npm run build` · Output: `dist`
3. **Settings → Environment Variables** 에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 추가
4. 배포 후 도메인을 Supabase의 Redirect URLs / Site URL 에 등록

```bash
# 로컬에서 배포 미리보기 (선택)
npm i -g vercel
vercel        # 프리뷰
vercel --prod # 프로덕션
```

## 정산 로직

두 명씩 비교해 스코어가 나쁜 사람이 좋은 사람에게 `타수차 × 타당금액 × 배판`을
지급하고, 전체 순잔액을 **최소 현금흐름(그리디)** 으로 단순화합니다. 스킨스는 홀마다
단독 최저 타수가 `걸린 스킨 수 × 타당금액`을 나머지 모두에게서 받고(`skinsResult`), 같은 방식으로
최소 송금으로 정리합니다. 핵심 로직은 `src/betting.ts` 에 있습니다.
